# 评测修正与仿真表格导出

基线：`da343a622c3338e375e37b78df4d6ed1053170e5`。

## 解决的问题

原来的在线汇总可能把未审核伪OK、初始化OK和模型自认标签当作评测真值；在线与固定测试的IoU统计方式、ROI范围也不一致。
本次将可靠审核子集与完整仿真在线流分开报告，统一以ROI内真实NG的前景micro IoU为主指标，并支持直接导出原15列汇报大表。

## 具体变化与影响

| 修改 | 原来的现象 | 现在的行为 |
|---|---|---|
| 评测真值来源 | 未审核伪OK、初始化和模型自认标签可能混入在线评测 | 在线审核指标仅使用人工审核/数据集真值，并披露排除数量与统计范围 |
| micro IoU | 在线与固定测试主值口径不同；较大漏检缺陷的影响不直观 | 先汇总交并像素再相除；漏检预测视为空，GT面积仍进入分母；逐图均值保留为辅助字段 |
| ROI | 预测或GT可能包含检测域以外的像素 | GT和预测采用相同ROI；跨ROI的YOLO实例mask裁剪到ROI内，完全在ROI外的NG排除并计数 |
| 缺失或无效GT | 可能被当作模型零分或用不完整样本输出完整指标 | 标记缺失、不可读、尺寸不符或空缺陷；分割主值为null并披露数量 |
| AUROC同分 | 消融实现漏算相等分数的贡献 | 复用主线实现，同分计0.5 |
| 缓存身份 | 样本数量或模型名相同仍可能复用失效缓存 | 核验输入、GT、ROI、权重和推理配置；预训练建库与校准依赖也参与校验 |
| 历史可视化 | 重算缓存可能修改旧报告硬链接的预测图 | 新推理身份使用独立目录，保留旧报告引用 |
| 批末快照 | 事后难以还原当时的训练池与候选状态 | 只读记录批末可用训练池、最新YOLO及状态，不提前写入NG分区 |
| 15列表格 | 需要手工拼接在线数据与模型演化 | 独立导出整批在线指标、最新YOLO实际训练数量及固定测试指标；被拒绝的候选也保留 |

例如：1像素缺陷完全检出，100像素缺陷漏检时，micro IoU为`1/101`；逐图平均仍为`0.5`，两者明确分开。
没有OK的批次，OK误报率为空；没有YOLO的批次，右侧模型列为空，不补0。

## 使用与兼容性

- 报告主列读取`iou_micro`；`mean_iou_all_ng`仍表示逐图均值，不能当作同口径主值。
- 在线审核子集为`reviewed_online_subset`，完整仿真事后统计为`complete_simulated_batch`，固定test独立报告。
- `export_simulation_table.py`读取完整真值只用于运行后的汇总，不回流训练池、阈值或晋升判断。
- `run_table_experiment.py`是此次服务器部署的实验执行器，需要部署时提供源码清单及数据/模型路径；通用生命周期入口仍是`run_lifecycle.py`。
- 旧缓存缺少新校验信息时会失效，首次运行可能重新建库或推理；历史报告不会自动改写。
- 沿用现有抽检、伪OK入训练池、训练里程碑、阈值优化目标和晋升门槛；不修改历史PPT数据或中断恢复规则。

指标定义见[METRICS.md](../METRICS.md)，实验矩阵与各列来源见[仿真实验方案](../experiments/table_simulation_20260922.md)。
