# 用当前 pipeline 填写 15 列大表的实验方案

## 实验目标和矩阵

保留原表的 10 列和右侧新增的 5 列，不增加 Precision、样本 ID 或技术编号列。
两处“平均 IoU”改为“micro IoU”。四个类别分别给出同样的表格，表内每行对应一个完整在线批次。

本轮先做 1 次 GPU 冒烟，再运行 4 个独立类别的完整仿真，均使用当前修复后的源码快照。
正式实验是 seed=42 的单次过程展示，不能据此声称有多随机种子的统计稳定性。
不同种子、不同 NG 比例和审核策略消融属于后续可选实验，本轮不混入主表。

| 设置 | 正式实验 |
|---|---|
| 数据 | `/gdata1/ninghao/dataset_523`，四类原始 train/val/test |
| 初始化 | 默认参考32、建库200、校准200；斜拍32/100/100；建库按现有代码必要时缩减 |
| 在线流 | train+val 去重、剔除 test 重复内容并扣除初始化后，剩余全部 OK/NG |
| 排序 | 当前默认 stratified，seed=42；这是控制各批 NG 比例的仿真，不宣称自然产线分布 |
| 批量 | 默认每批200，斜拍每批100；末批按剩余实际数量 |
| 复核 | 预测NG全复核，预测OK按当前分段抽检，伪OK按当前配置入训练池 |
| YOLO | 首次40个有效NG，随后按当前类别里程碑触发；每批只训练最高到期里程碑 |
| 训练 | YOLO26s-seg，100 epochs、1024、batch4、seed42、last.pt，所有类别一致 |
| 晋升 | 沿用当前离线门槛和未来批次影子门槛，不因测试集结果调整 |
| 独立评测 | 固定原 test，每个训练出的候选均评测，包含被拒绝或尚未晋升的版本 |
| 指标 | ROI 内真实NG前景 micro IoU；Recall；OK误报率。漏检预测视为空 |

若某批越过多个里程碑，不人为补训练被跳过的版本。流结束后仍在影子的候选保留“影子中”，不强行晋升。
固定 test 沿用现有数据，不能额外声称它从未被过去人工方法选择使用。

## 每列表述、来源与时间点

| 列 | 定义和记录 |
|---|---|
| 批次 | 类别内批号，从1递增 |
| 输入数 | 本批实际执行推理的图片数 |
| 实际的输入OK/NG数 | 全部输入的原始文件夹真值；ROI 外缺陷的排除量另在机器报告记录 |
| 模型推理的OK/NG数 | 本批正式模型实际判定数，不用最新候选回放替代 |
| 需要人工打标的数量 | 实际进入复核的图片数，去重；这是仿真审核图数，不是假定的人工作时 |
| 可用于模型训练OK/NG数 | 截至批末累计可用训练池：OK含当前允许的伪OK，NG排除固定哈希划分的校准部分及ROI外缺陷；未按400张上限抽样 |
| 正式模型 | 本批开始时实际服务的模型；批末晋升从下一批生效 |
| 在线Recall | 整批仿真真值上的TP/(TP+FN)，由独立事后评测器计算 |
| 在线OK误报率 | 整批仿真真值上的FP/(FP+TN) |
| 在线micro IoU | 本批有效真实NG的最终预测交集之和/并集之和 |
| 最新YOLO（状态） | 截至本批训练、离线比较和影子判定结束时，最新训练完成的YOLO及当时状态 |
| 该YOLO实际训练OK/NG数 | 对应模型summary的`dataset_stats.train`，使用ROI处理后的真实训练数量，不含校准集 |
| YOLO独立评测Recall | 右侧该模型在同一固定test上的Recall |
| YOLO独立评测OK误报率 | 同一模型、同一固定test的OK误报率 |
| YOLO独立评测micro IoU | 同一模型、同一固定test的micro IoU |

尚无YOLO的批次右侧填“—”及空值；同一版本延续时重复填入并更新批末状态。
比例保存原始小数，展示为百分比；IoU为0–1。某项分母为0或GT不完整时留为不可用，不能补0。
不同类别不得混算macro/micro或直接平均批次比例。需要汇总时，从逐批TP/FP/FN/TN和交并像素数重新计算。

## 必须保存的原始证据

1. 源码基线提交、全部源码文件SHA256、未提交修改快照、完整配置、环境版本、权重SHA256、PBS编号与日志。
2. 初始化、在线流、固定test的冻结清单，以及图片和NG mask的内容哈希；检查角色间重复、GT完整性、尺寸与极性。
3. 每图：批号、输入路径、当时正式模型和阈值、得分与判定、预测mask、复核来源和结果。仿真完整真值仅供事后评测。
4. 每批：审核图数、抽检统计、审核子集指标，以及批末训练池、最新YOLO版本和状态快照。
5. 每个YOLO：训练/校准清单和实际计数、训练参数、last.pt及哈希、阈值、训练时间、离线门槛、影子窗口和晋升结论。
6. 固定test逐图结果、分类混淆计数、ROI排除数、无效GT数、最终交并像素数与报告目录。

批末快照只读现有数据库和注册表，不提前执行NG分区写入，不引入额外真值。
`export_simulation_table.py` 在生命周期运行结束后读取完整仿真真值，只写实验汇总目录，不写训练池、阈值或晋升状态。

## 执行与验收

先在独立环境做全量CPU测试、权重与路径检查。GPU冒烟使用外圆ROI类别的独立小流、1 epoch和全审核，检验
冷启动、训练、阈值、固定test与导出链路；这些结果不能填入正式大表。
冒烟通过后四类正式实验分别通过PBS提交，各自独立workspace/cache/日志，使用共享只读冻结输入。

完整性要求：所有预定流图像恰好处理一次，所有预期批次有批末快照，未审核/未完成状态明确检查；
实际训练出的每个模型有checkpoint、阈值与固定test报告；各版本固定test组成一致；
独立导出的大表行数等于完成批次数，输入OK+NG=输入数、预测OK+NG=输入数、交集不超过并集。
同时核验PBS退出状态和实验`status.json`，不能仅根据作业从队列消失判断成功。

当前上游恢复逻辑存在已知边界，本轮使用全新运行目录，PBS禁止自动重跑。失败时先诊断，保留旧输出并使用明确retry目录，不能直接宣称续跑完成。
